## ⚠️ 上机前先看这四条（别踩坑）

1. **只适用于 Olympus E-M10 II，固件必须是 `E120 1400 0000 0000`**，别的机型/版本刷了大概率变砖。
2. **包放在卡上是 `DCOLYMP/E1209999.BIN`，官方 `E1200001.BIN` 一个字节都别动**——那是恢复用的。
3. **本补丁改变的是成像**：V/N 已达到参考误差（灰阶 ≈4 码），**M/P 在高光段仍偏亮约 20 码、色度差 ΔE00 ≤6**，预览与成片有轻微差异。想要"完全等于参考胶片"的，现在还不是。
4. **刷机有风险，先学会恢复**：拔卡重刷官方固件即可回原厂；`SAFETY.md` 写了步骤，出问题别慌、别连着刷第二包。

## 这是什么

一个针对 **E-M10 Mark II** 机身 JPEG 色彩管线的实验项目。做法是：把官方固件按容器格式解析（逐字节取反 + 16 字节列置换），定位与影调曲线、色彩矩阵、色度参数、菜单字符串相关的数据区，然后用「补丁 + 校验」的方式做小范围参数替换，全部结论在真机上逐项核对。

产出的东西是**补丁定义**（`patches/*.patch`，纯文本，几 KB），不是固件本体：你需要自备官方固件，本地打完补丁自己拷卡。仓库里没有任何 `*.BIN`、没有任何官方或商业 LUT、没有实拍照片。

四档风格在包里统一写作 `look-01 … look-04`（风格参考），具体对应的参考对象见 `docs/STATUS.md` §2。固件里的菜单名、EXIF 标记、文件命名都不带第三方商标。

## 已知限制（三条）

先说结论：**四档里 V、N 两档在真机上达标；M、P 两档有已知偏差。**

1. **M/P 高光偏亮约 +20 码**。M（look-03）真机实测偏差 `+22/+16/+8/−2/−1/+1`，P（look-04）为 `+21/+12/+7/0/−8/−4`：暗部与中间调贴合，高光段系统性偏高约 20 个 8-bit 码值。原因是高光段曲线受机内另一条支路钳制，目前只压到这一步。
2. **预览与成片仍有偏差（机制已定位，不再为它单独刷机）**。CPU 里没有显示专用 gamma / 3D LUT / 环境光增益；差异来自 look 曲线块的两条装配路径，以及 LV 帧未清零的五拨盘弯曲。`PREVIEW_FIX2`（0x604B9ECF，`C8→CA`）已打进补丁；真机目视只剩细微差别，但仍不是像素级一致，预览只当作「接近」。
3. **色度误差 ΔE00 ≤ 6**。色彩矩阵取自公开参考数值再做拟合，逐点色差上限约 6 个 ΔE00 单位，肉眼在饱和色块上可辨，未做到逐点一致。

另外 V 档的色度退饱和（L62）在真机上会把整片拉绿，已回滚；V 的色度偏差 5.82 ΔE00 属于上面第 3 条的范围。

这些限制在 `docs/STATUS.md` §3、`docs/analysis/acceptance-22.md` 里有逐项的真机数值，`research/02-preview-flatten.md` 有预览成因分析。**不承诺「完美复刻」，也不支持 E-M10 系列的其它机型。**

## 怎么用

完整五步见 [`QUICKSTART.md`](QUICKSTART.md)。核心命令只有一条：

```bash
python tools/mkpatch.py OLY_E_120_1400_0000_0000.BIN \
  --out E1209999.BIN --patch-file patches/RELEASE_v1.patch
```

打完把 `E1209999.BIN` 拷到卡的 `DCOLYMP\` 目录（卡根下自建），插卡开机验证。打之前请先按 `SAFETY.md` 校验官方包的 sha256——补丁只对 `E120 1400 0000 0000` 这一版有效，字节不对必须停手。

工具里的路径都可以用环境变量覆盖：`EM10FW_ROOT`（工作区根，默认 `.`）、`EM10FW_CARD`（卡根，默认 `.`）。旧的盘符硬编码已经全部参数化，默认值不再指向任何具体盘。
