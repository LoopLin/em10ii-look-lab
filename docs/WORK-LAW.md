# 工作律（每一代必读，优先级高于任何"经验"）

> 立：2026-11-22。起因：M1 / M1b 两包连续把相机刷成开机循环——桩位 `0x60672C58` 在文件里是"982 B 全 FF、0 引用"，被当成"可写口袋"直接用，但它**运行时不可执行**。这是流程错误，不是运气问题。

## 0. 一句话

**先看懂代码，再写代码；先上模拟器，再上相机。**

## 1. 顺序（不许跳步、不许并行偷跑）

| 步 | 产出 | 没做到就不许进下一步 |
|---|---|---|
| 1. **反汇编** | 目标路径的完整指令级阅读：函数入口、调用点、分支、寄存器约定 | 只有"大致是这里"不算 |
| 2. **代码地图** | ①函数入口表 ②数据结构（字段偏移/大小/类型）③调用点（谁调谁、什么条件）④**跨区通道**（哪块给哪块发什么指令/数据） | 缺任何一项都算没地图 |
| 3. **写进 docs** | 上面全部落到 `docs/map/` 的对应文件，标证据等级 | 只在脑子里的地图等于没有 |
| 4. **模拟器验证** | 用模拟器跑**打过补丁的镜像**，证明这条路径真的执行到、值真的被消费 | **必须带 `--patch`**（不带就是原版，见 §5） |
| 5. **模型门 + 五道门 + 能力回归** | 先 `tools/model_gate.py`（question / model / prediction / falsifier / observables≥2）→ 再 `audit_beta_pack` → `patch_check --reach` → libsim(`closed:true`) → `second_verify --base stock` → `check_stub_region` → `verify_caps` 打 `CAPS_OK n/n` | 模型门不过 = 不许构建；`STUB_FAIL`/`CAPS_FAIL` = 作废 |
| 6. **上机** | 一次一包，一包**只回答一个问题** | 一包多问 = 修不动 |

## 2. 必须看懂的两条链（做任何新功能之前）

### 2.1 开机链
- 从**复位向量**开始：找 vector table → reset entry → 启动函数 → 各子系统初始化 → 第一次进入 ISP / LV。
- 必须能回答：**我们的钩点，是在开机第几步被第一次执行的？**（M1b 就死在这：它在启动早期被执行，而跳转目标不可执行。）

### 2.2 快门链
- 半按 → AE/AF → 全按 → 曝光 → ISP 流水线 → JPEG/ORF 封装 → 写卡。
- 必须能回答：**哪个阶段是"一次"的、哪个是"每帧"的**。阻塞式 I/O 只许放在"一次"的阶段（M1 把 `fileif_*` 放进逐帧 tone 上传器，方向就错了）。

## 3. 地址的四种性质，必须分开证明

| 性质 | 怎么证 | 反例 |
|---|---|---|
| 文件里存在 | 解容器后逐字节读 | — |
| 被映射 | 运行时证据（真机读过/写过、模拟器内存映射） | `0x60672C58` 就是这样被误判的 |
| **可执行** | 同段有已验证代码 / 模拟器在该地址成功取指 | **M1/M1b** |
| 无引用 | 全镜像 u32 + PC 相对引用穷举 | "没人引用"不代表"能跑" |

**"全 FF + 0 引用"只说明它没被当成数据用过，不能推出可以执行。**

## 4. 代码地图的最小内容

一份能用的地图必须能回答下面五问，且每条都带证据等级（真机/模拟/静态/推理）：

1. 这个功能的入口函数是谁？谁调它、什么条件下调？
2. 它读写哪些结构？字段偏移、大小、取值范围？
3. 它把什么交给谁？（跨区通道：命令字、缓冲区、DMA、共享内存、寄存器）
4. 它在开机链/快门链的第几步被执行？一次还是每帧？
5. 如果改它，谁会被连带影响？（调用方、同结构的使用者、缓存/双缓冲）

## 5. 模拟器纪律

- 本仓库模拟器：`tools/omemu_winfix.py` + `.tmp/*.omemu.json` 配置；跑补丁镜像时**必须**带 `--patch`，否则跑的是原版，看到的一切都不算证据。
- 模拟器通过的**含义**：这段代码在这个上下文里能执行、值被消费。
- 模拟器通过的**不含义**：真机能开机、时序没问题、外设有响应。
- **真机 + 模拟同时复现同一现象，才算补丁生效。**

### 5.1 三台模拟器，分工与强制用途（用户 2026-11-22 定，长期有效）

| 工具 | 是什么 | 必须用它证明什么 |
| :-- | :-- | :-- |
| **`libsim`** | GNU binutils `sim/mn10300`（`.tmp/olya/toolchains/mn103-gnu-build`，`PFMN002` 协议，内存区域由我们手写） | 内核指令级：从复位向量/某入口跑，能不能执行、跳到哪、哪块内存被写。**涉及内核指令或固件结构的改动必须过。** |
| **`strict`**（fishku `penf_emulator` + `mn103_strict.patch`） | 同一台引擎，前端更严：`Region(name, lo, bytes, perm)` 白名单，未声明访问即停 | 同上，但**独立实现**，用来交叉验证 `libsim` 的结论。**必须与 `libsim` 同时过。** |
| **`om-emu`** | 本机整机/GUI 模拟器（固件 + 外设行为），跑补丁必须 `--patch` | 整机行为：菜单、模式分发、**拍摄一张**，并从模拟照片的 EXIF / 卡上的文件里读实地值。 |

- **om-emu 是本项目最便宜的观测通道**：`tools/emu_shot_trace.mjs`（拍一张 + 对指定地址范围下 watchpoint，按 PC 聚合）、`tools/emu_pc_hits.mjs`（统计一组 PC 在一张照片内被命中多少次）、`tools/emu_param_probe.mjs`、`tools/emu_struct_scan.mjs` 已经能跑。⇒ **凡是要"读一个字段值"，先用它在模拟照片/EXIF 上读，不得直接排一次刷机。**
- om-emu 还能**复现崩溃**：补丁导致开机重启时，模拟器里同样起不来，可以在不碰相机的情况下做二分。
- 三者都不模拟 ISP 出图质量，也都不证明"真机能开机"——那条仍要真机。

## 6. 先例项目里的模拟器（EP7 / Caduceus）

- `Caduceus`（E-P7）用的不是自研模拟器，而是 **fishcu/oly_fw_analysis 的 MN103 emulator harness**，以 submodule 形式引入：`.tmp/cx/external/oly_fw_analysis`（`.gitmodules` 指向 `https://github.com/fishcu/oly_fw_analysis`）。
- 它的 README 明确写着：**每个补丁先在该 CPU 模拟器里通过，才允许上相机**——这正是我们这次缺的那一步。
- 我们的目标机型同属 MN103 家族（TruePic VIII），harness 可借鉴来跑"补丁是否被读到、路径是否执行"；但**外设/内存映射要按 E-M10 II 自己建**，不能直接套 E-P7 的地址。
- 具体接口（如何加载镜像、如何下断点、如何读寄存器）待 `boot-map` 子智能体给出后补到本节。

| 事故 | 违反了什么 | 代价 |

### 5.2 om-emu 的边界（2026-11-22 实测，务必先读再引用）

- 它能**应用**我们的补丁（`tools/omemu_patch.py` 负责把 `blk N:0xOFF=HEX` 转成它认的 JSON，偏移是 identity，selftest 2000/2000 全等）。
- 但 **tone/ISP 那一段固件它不执行**：喂 M1b 补丁后 `0x60479A2B` 与 `0x60672C58` 的命中次数都是 **0**，整机也不重启——它走的是高层模型（HLE）。
- ⇒ **凡是"补丁会不会被这段代码执行 / 会不会崩"的问题，om-emu 的结论一律不算证据**；这类问题只能用 `libsim` / `strict`（有界例程）或真机。
- ⇒ om-emu 给出的 EXIF **可能是模型自己编的**，在验证它与真机 EXIF 逐字段一致之前，不得把它的 EXIF 当作"我们补丁写入的值"。
- 它可靠的用途：界面/菜单/模式分发、整机流程是否走通、PC 命中统计（对**它自己执行**的那部分路径）。

### 5.3 五道门的第 5 道与"能力回归"（2026-11-22 新增）

| 门 | 命令 | 它回答什么问题 | 失败长什么样 |
|---|---|---|---|
| ⑤ 桩位合法性 | `python tools/check_stub_region.py --target T --caller C` | 这个跳转目标**运行时有没有字节**、装载是否早于调用方、后面还剩多少空间 | `STUB_FAIL …` |
| 能力回归 | `python tools/verify_caps.py --bin build/XXX.BIN` | tone 四表 / N 兜底 / 弯曲门 / 四矩阵 / 色度块 / UI 名 / 桩完整 / 桩位 / SD API / 无越界，**十条能力是否都还成立** | `CAPS_FAIL k/n` |

- `check_stub_region.py --self-test` 内置 5 条用例（含 M1 的 `0x60672C58` 必须 FAIL），改动该工具后先跑它。
- `verify_caps.py` 的断言清单落在 `docs/firmware/CAPABILITIES.md`；**新增能力 = 先在那里加一条断言**，否则不许进成品。
- 2026-11-22 实测：`RELEASE_v1` → `CAPS_OK 10/10`；桩位 4/4 OK（SD/SU/blk13 在 seg3、MX 池在 seg1）。


## 8. 三种"看起来在干活、其实在骗自己"的坏习惯（2026-11-22 归纳）

> 这三条都真实发生过，都直接导致过废包或白刷。写在这里是给后代当**禁令**，不是当故事。

### 8.1 把文档当事实（不重新算一遍）

- **事故**：M1 选桩位时，看到 `docs/map/mem-regions.md` 写着"`0x60672C58` 附近 982 B 全 FF、0 引用"，就直接当成"可以执行"，没有再算段表。真机两次开机重启。
- **真相**：段加载器只拷 `[dst, used_end)`；`0x60662000..0x60673000` 不被任何段拷贝（`docs/map/exec-map.md` 末节）。"FF + 0 引用"只证明**没被引用**，不证明**被装载**，更不证明**可执行**。
- **禁令**：文档里的每个地址，用之前必须能被一条命令复算（`tools/execmap.py`、`tools/second_verify.py`、反汇编）。**算不出来 = 未证 = 不许用**。文档写错时，先改文档再动手。

### 8.2 把刷机当测量仪

- **事故**：为了读一个字段值（`k=`、`key=`、`ctx+0x1230`）就专门做一个探针包、刷一次、拍一张、再读 EXIF。tone 曲线曾用约 25 个包逼近，一包只带回一个数。
- **真相**：`om-emu` 早就能模拟拍摄（`tools/emu_shot_trace.mjs`、`emu_pc_hits.mjs`），一次探针包就能把整条阶梯/曲线写进一次拍摄；而"读数"根本不需要占用真机次数。
- **禁令**：刷机次数只分配给**确认**，不分配给**探索**。任何"再刷一包看看某个值"的念头，先问：这个值能不能在模拟拍摄/已有照片/离线管线里读出来？能，就不许刷。

### 8.3 相信自检的"结果"而不看它怎么退出

- **事故**：`tools/flash_gate.py` 那次因为模拟记录文件名不匹配而 `FAIL ... exit(1)`，我用 `| tail -4` 把失败行和退出码一起截掉，只看到"像成功"的残片，误判写卡成功；随后一轮真机判读全部作废。
- **真相**：管道的退出码是管道里**最后一条命令**的，`tail` 永远返回 0。
- **禁令**：① 关键工具必须打印唯一可认的哨兵行（如 `CARD_OK sha=…`），只认哨兵；② 不许对会失败的命令用 `| tail`/`| head` 收尾，要收尾就 `set -o pipefail` 或先落盘再读；③ 写卡后必须**回读 sha**，与预期逐字比。

## 9. 模型门与刷卡制（2026-11-22 立，防"规则退化成老样子"）

> 起因：这一代写下 §1 之后，仍有 L39/L42/L44/L47/L48/L52/L53/L54/L55 等十来包在追同一个数字，
> 以及 M1、M1b 两包把相机刷成开机循环。教训不是"没写规则"，是**规则没有产出物、也没有成本**——
> 同一个执行者既解释规则又给例外，规则就一定会被豁免。所以这一节全部做成**脚本和模板**。

### 9.1 模型门（理解门，不是安全门）

- **工具**：`tools/model_gate.py`；**模板**：`docs/firmware/MODEL-TEMPLATE.json`
- **位置**：与包同名，`build/<NAME>.model.json`
- **必须包含**：`question`（一个问题）/ `model`（数据流或公式，写到地址或字段）/ `prediction`（≥1 条，含 `values` 与 `tolerance`）/ `falsifier`（什么结果会推翻它）/ `observables`（≥2 个可离线判读的量）
- **硬点**：写不出 `falsifier` 就是在猜；`observables` 少于 2 个就是一包只带回一个数。
- 实测：合格文件打印 `MODEL_OK <file> 预测 n 条 / 可读出 m 个`；不合格逐条列出并 `exit 1`。

### 9.2 刷卡制（刷机预算）

- **工具**：`tools/cards.py`；**账本**：`build/cards.json`
- 一代 **12 张**；刷一次消耗一张（`use --pkg X --card N`），用完拒绝。
- 例外**只能由用户给**：`exception --pkg X --reason "用户允许：…"`，写进账本，不消耗额度但留痕。
- 作用不是省刷机，是把决策从"要不要刷"改成"值不值我十二分之一"——这一代只有 12 张，L52–L55 那四包不会存在。

### 9.3 唯一写卡入口

- **工具**：`tools/flash.py`（模型门 → 刷卡 → `tools/flash_gate.py --copy`）
- 它只认 `flash_gate` 打印的 `CARD_OK sha=…`；模型门不过直接 `exit 1`，刷卡不够 `exit 2`，写卡失败 `exit 3`。
- **`tools/flash_gate.py` 不再单独用来上机**：它只负责"这包合法吗、卡对不对"，不负责"你在验证什么"。
- 跳过模型门的唯一合法方式：`--exception "用户允许：…"`，并在 `build/cards.json` 留痕。

### 9.4 红旗清单（用户可用的刹车，说一句就得停）

1. `这包验证哪个模型？`
2. `预测值是多少？`
3. `它会带回几个数？`
4. `这是第几张卡？`
5. `离线为什么定不了？`

同一代被红旗叫停累计 **4 次**（同一句四次，或四次不同句，都算）→ 强制**地图日**：**12 小时**内不许构建、不许刷，只许读反汇编、写 `docs/map/`。用户明确说“继续/允许”时，限制当场解除；解除原因记进当天的 `docs/map/` 工作记录。

### 9.5 为什么这次可能不会退化

| 老办法（已证会退化） | 现在的约束 |
|---|---|
| 规则写在散文里，靠自觉 | 模型门是脚本，缺项 `exit 1`，构建/写卡走不动 |
| 例外权在执行者手里 | 例外必须用户给，且写进账本 |
| 刷机免费，试错无成本 | 一代 12 张，消耗即少 |
| "一包一问"是口号 | `observables ≥2` 是可检查字段 |
| 规则很长，赶时间就跳过 | §9 只有三种机制 + 五句红旗 |

## 10. 任务派发预算（2026-11-22 用户定，长期有效）

- 团队最多派发**两轮**；总任务数不超过实际子智能体数的 2 倍（五个智能体 ≤10；一个智能体只做一件事时 ≤2）。
- 两轮之外不再派生新任务；中途发现的新缺口写进报告或“已知缺口”，等下一轮用户授权。
- 派发前先定好两轮清单；第二轮只补第一轮暴露的、必须补的项，不把每个检查项都开成新任务。
