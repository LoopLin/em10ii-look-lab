**机制补充（2026-11-22 00:23，读第四代 field-access 复核记录后）**：tone 真链路是
`CtxC+0x3C0`（色彩记录指针）→ `记录+0x08`（tone 表指针）→ 拷进影子副本 `CtxA+0x1234` → 上传器；

### 8.1 C 线结论（2026-11-21，L30 的 ORF+JPEG 离线反解）

用 `M_k/256 @ x` → `i = round(255*srgb(2.5*Y))` → 取 L30 表 `T` → 与 L24 探针得到的 `h(T)` 比：

| 档 | 残差范围 | 判读 |
| :-- | :-- | :-- |
| P（k=4） | −4.0 … +8.1 | 模型成立 |
| V（k=1） | −4 … −44 | 模型不成立，实测比预测低 |
| M（k=3） | −6 … −61 | 模型不成立，实测比预测低 |

**推论（等级：真机数据 + 推理）**：同一个表值 `T` 在 L24（恒等表）与 L30（牛顿表）给出相差 20–40 的输出，说明查表之后的级**不是只吃表值**——它同时还吃查表前的原始值（混合/对比度作用在原信号上）。所以"把表值往两端推"在两端无效：那一段的贡献权重接近 0。

**下一步（不再盲推表）**：固定场景做 A/B，两张表只差某一个索引处的值，量输出差 → 得到每档的灵敏度 `w(i)`；或直接在固件里找这个"表值 + 原值"的混合点（`ctx+0xE/0x424/8/9` 一带）。
