# 05 · 半按入口怎么选

> Status: 已定论（入口成立；loader 未成）
> Evidence: 真机（键码 0x100）+ 模拟（键码/边沿）
> 适用范围：E-M10 II / E120 1400 0000 0000

## 问题

想用“半按一次”触发读卡/加载。问题是：S1（半按）在固件里的入口到底在哪？

## 原来的判断

一开始按“按钮服务”找，看到 `SERV_S1` 就以为是 UI 半按入口；也看到 `0x6018005D` 的 `d0==5`，以为 5 就是 S1 键码。

这两条都不对。

## 怎么查

1. 先找静态入口：键表、服务表、事件分发；
2. 用模拟器打出按键，观察每个候选入口的 `d0/d2`；
3. 区分“入口被调用”和“参数是键码”；
4. 真机只花一张卡确认。

## 结果

### 1. 没有静态 S1 专属入口

- `SERV_S1` 实际是 `0x9B7xxxxx` 硬件时序服务（IRQ 号运行期分配），不是 UI 半按；
- 键表 `0x601A90EC` 的 p1/p2 指向 `0x615Dxxxx`，超出镜像末尾 `0x61480FE0`，运行期构造。

### 2. 两级漏斗

- `0x6018005D`：每次按键消息一次，188 B；唯一调用者链 `0x6017FBD6 → 0x6017FB62 → UI_IN 0x6017E21E` 消息循环。
  - 这里的 `d0` 是 **ADC 源编号**（S1=5，S2=8，OK=4），不是键码。
- `0x601800D4`：每次边沿一次，5 B `cd 90 00 c0 18`，只在“字节变化位”执行，按下/松开各一次。
- `0x60180164`：边沿处理器的入口；这里 `d0` 才是**键码**。

### 3. 真机确认

P0S-0B 包在 `0x60180164` 记录 `d0`：

- 第一张空白；
- 第二、三张：`H=1 K=100 D=00 S=0001 N=06`。

`H=1` 证明入口被调用，`K=100` 证明 `d0==0x100`。**S1 键码 = 0x100，真机已证。**

`N=06` 是 key message 条数，不是半按次数；`D=00` 是桩另存的 `a0` 低字节，不是键码。

## 被推翻的结论

- “`SERV_S1` 就是 UI 半按” → 错，是硬件服务。
- “`0x6018005D` 的 `d0==5` 就是 S1” → 错，5 是 ADC 源编号。
- “入口被调就算成功” → 不够；还要看参数是不是键码、方向是不是按下。

## 影响

- 半按触发点应选 `0x60180164`，不要用 `0x6018005D` 的 `d0==5`。
- 还要处理方向位 `a1`：按下/松开都可能进同一个 handler；如果不判方向，松开也可能触发。
- 半按 context 调 fileif 是否安全仍未证；P0S-0B 只记录，不读卡。

## 证据与未证

- 真机：`H=1 K=100`；
- 模拟：`0x100`、`0x101`、`0x89` 的边沿/键码；
- 未证：半按 context 调 fileif 是否阻塞；一次半按是否只产生一个有效边沿（按下/松开都算）。
