# 03 · HSL 标准档为什么用不上

> Status: 结论已定；P0 测量未做，补丁未出
> Evidence: 静态已证（分发/分支/表内容）；真机未接
> 适用范围：E-M10 II / E120 1400 0000 0000

## 问题

库里有 HSL 数据，也有 HSL builder，但标准拍照档（V/N/M/P）看起来没有用上 HSL。到底是表不对，还是调用没接？

## 原来的判断

历史上试过三种修法：

1. 改 `0x604B983F/48` 的 `nop`；
2. 写 `ctx+0x24A`；
3. 改 `0x604BAB27` 的 call 目标。

后来证明这三条都不成立：前两条在标准档不可达；第三条会破坏调用帧。

## 怎么查

1. 从 `0x604B500E` 分发器开始读模式分支；
2. 追标准档的 builder/主体；
3. 读 HSL 主体入口的两道门；
4. 直接检查真表与平表的 mask、记录内容；
5. 用反汇编确认 nop / call 帧。

## 结果

### 分发

`0x604B500E` 按 `ctx+0x10` 分流：

- `0/0x0E`（普通拍照）→ `0x604BAB14` → `0x604BA774` → **`0x604B974D`（HSL 主体）**；
- `3`（ART）→ `0x604BAB67/DB` → `0x604BA83F` → `0x604B97F8`。

`0x604BA83F` 全镜像只有 `0x604BAB68/DC` 两个调用点。

### 标准档确实进 HSL 主体，但走关闭支

`0x604B974D` 每次标准链都执行，但：

- `ctx+0x0C == 0xF00D` → 跳到 `0x604B9738`（关闭/旁路）；
- 第二道门是 `*(obj+0x38)` 的 bit28，不只是 `ctx+0x3C0`。

所以“标准档不进 HSL”只说对了一半：它进主体，但门关着。

### 真表不是全 0

`0x605F5A64` 的 3028 B：

- 108 条 28 B 记录里 **102 条非 0**；
- 只有 mask `+0xBD0 = 0`；
- n11 的 mask 是 `0x41 << i` 算出来的，不读这一格。

平表 `0x605F0798`：

- 106/108 条非 0；
- mask `0x07DF`。

“真表全 0，所以标准档没数据”这个旧结论是错的。

### 三条旧修法的问题

1. `0x604B983F/48` 的 `nop` 在 flag==0 支，标准档不进选择器，改它无效。
2. `ctx+0x24A` 是“参数集已装”标记，只选 A/B 组，不是 HSL 开关。
3. `0x604BAB27` 原为 `cd 4d fc f0 28`（call `0x604BA774`，帧 `[d2,d3,a2,a3],0x28`）。改指 `0x604BAB67` 会跳过矩阵/六轴/HSL 主体；如果非要改，调用帧必须同时改为 `cd 40 00 20 08`，否则栈不平衡。

补充：mn10300 的 `nop` 是 `cb`；`00` 是 `clr d0`；`c9 00` 是 bne 自跳。不要按 x86 直觉填。

## 被推翻的结论

- “真表全 0” → 错；102/108 非 0。
- “改 `0x604B983F/48` 就能打开 HSL” → 错；不可达。
- “写 `ctx+0x24A` 就能让标准档用 HSL” → 错；它不是开关。
- “直接改 `0x604BAB27` 的 call 目标” → 会坏栈/跳过主体。

## 影响

- 在出补丁前，先做 P0 只读测量：
  - `ctx+0x3C0`
  - `*(obj+0x38)` bit28
  - `ctx+0x0C`
- 如果标准档门确实能开，再决定“接调用 + 清门 + 发布到 ISP”三件事怎么同时成立。
- 第三件（发布到 ISP）当前静态不可达，不能只凭“表改了”就上卡。

## 证据与未证

- 静态已证：分发、主体入口、两道门、真表/平表内容、call 帧；
- 未证：标准档运行时这些门是否可满足；P0 未做；
- 未证：HSL 结果是否真的发布到 ISP（G7）。
