# 02 · 预览为什么偏平

> Status: 机制已定位；不再为预览单独刷机
> Evidence: 真机目视 + 静态已证（函数、分支、CPU→ISP 站点）
> 适用范围：E-M10 II / E120 1400 0000 0000

## 问题

相机屏幕上的实时取景（LV）看起来比直出 JPEG 更平、更灰、更“没有对比度”。很容易误判成“预览没有走 look 参数”或“预览是另一条 3D LUT”。

## 原来的判断

早期判断是“预览链和成片链分岔，预览吃的是另一套参数”，所以曾尝试单独修预览。

## 怎么查

1. 找 tone/矩阵/色度的 getter 和两个外部调用者；
2. 对比 LV 与成片的装箱方式；
3. 扫 CPU→ISP 的写点，找有没有显示专用 gamma / 3D LUT / 环境光增益；
4. 看 LV 帧与成片帧对五拨盘弯曲、清零逻辑的差异。

## 结果

### 1. 只有一个 getter

`0x604B4B24` 的外部 caller 只有两个：

- `0x604AA297`：LV；
- `0x604B4E29`：成片。

LV 路径：`0x6046AAB6 → 0x6046E9B5 → 0x6046EDC0 → 0x6046EAAF`。它**完整跑一遍模式应用**，tone/矩阵/色度都会吃我们改的数据。所以“预览完全不跟成片”是错的。

### 2. 0x9C 不是 156 B

`0x604AA312` 的 `85 9c` 常被读成“复制 0x9C=156 B”。实际 `0x9C` 是**循环初值 -100**，`inc` 到 0 共 **100 次**。

- LV：`CtxB+0x1D..+0x80`，100 B；
- 成片：同一个 getter 返回的数据，按 16×u32×2 交织，最大源偏移 +0x62，落在 99 B+1 pad；
- 零拷贝分支：98 B（+0x1D..+0x7F，中间有 1 B 空隙）。

结论：**两边是同一份数据，两种装箱**，不是两套参数。

### 3. CPU 里没有显示专用 gamma/3D LUT/环境光增益

扫 `0x9E00xxxx`：148 个 distinct 地址、319 个站点；真正的 tone 目的地只有：

- `0x9E00A400`（`0x60478A6C`）
- `0x9E00CC00`（`0x60478A8E`）

没有第二块显示 gamma、3D LUT、环境光增益的写入。

### 4. 五拨盘弯曲只在成片清零

- 弯曲门：`0x604B9F11..F50`，读 `S+0x3B4`；
- 本体：`0x60482199`；
- 拨盘：`model+0x159C..0x15A5`，有效字节 `model+0x1616`；
- 成片侧四档清零 `0x604861AC..0x604861C0`；
- LV 侧只有 `0x60476D8E` 哨兵初始化，没有同样的清零。

## 被推翻的结论

- “预览没走 look 参数” → 错；它走同一套模式应用。
- “预览是另一条 3D LUT” → CPU 侧没有这个写点。
- “0x9C=156 B” → 错；是 100 B。
- “预览偏平可以靠再打一个预览补丁解决” → 不是参数问题，是显示侧/装配路径差异。

## 影响

- 不再为预览单独刷机；预览只作为“接近”验收，不作为像素级判据。
- 如果以后要追像素级，目标应该是显示侧（面板/EVF/编码后处理），不是 CPU 里的色彩表。
- LOOKS/参数替换仍会让预览跟着变；不要因为“预览有差异”就否定参数替换。

## 证据与未证

- 真机：目视只剩细微差别；
- 静态已证：getter、两个 caller、100 B 装箱、CPU→ISP 站点、五拨盘门；
- 未证：面板/EVF 像素侧的具体响应（CPU 外），以及第二级显示 gamma 的精确位置。
